# Android: Сходи — куда сходить?

Android 2.0.0 использует локальную сборку каталога. Веб-версия остаётся без рекламы.
Имя пакета: ru.moorkis.shodi. Тестовый пакет: ru.moorkis.shodi.debug.
Минимальная версия Android: 8.0 (API 26).

## Проверка

В Actions → Android APK тестовый APK собирается без личных данных, с демо-блоками Яндекса и временной debug-подписью. Установите его на устройство и проверьте офлайн-поиск, маршруты, возврат, поворот экрана, тему, внешние ссылки и рекламные форматы. Не публикуйте debug APK в RuStore.

## Подпись и реальные объявления

Создайте один постоянный ключ подписи локально (Android Studio или keytool); сделайте защищённую резервную копию вне GitHub. Для последующих обновлений используйте тот же ключ. Не передавайте ключ и пароли в чат, коммиты, issue, логи и публичные артефакты.

В Settings → Environments создайте android-release, разрешите деплой только из main; при наличии возможности настройте подтверждение владельцем. Добавьте secrets:

- SHODI_KEYSTORE_B64 — base64-файл хранилища ключей
- SHODI_STORE_PASSWORD — пароль хранилища
- SHODI_KEY_ALIAS — псевдоним ключа
- SHODI_KEY_PASSWORD — пароль ключа
- SHODI_BANNER_ID, SHODI_INTERSTITIAL_ID, SHODI_NATIVE_ID — ID ваших трёх рекламных блоков

Реальные рекламные ID не являются паролями: они неизбежно присутствуют в производственном APK и извлекаются из него. Секреты защищают их от появления в исходниках и логах, но не скрывают от владельцев APK. Ключ подписи и пароли никогда не должны попадать в APK. Сборка production запускается вручную на main после успешного тестового задания, без автоматической публикации в магазин. Не загружайте секреты до проверки кода и зависимостей. Публичные Actions-артефакты могут скачивать пользователи с доступом к репозиторию; если даже распространение подписанного APK до публикации нежелательно, соберите его локально.

## Конфиденциальность

Маршруты находятся в локальном WebView, не передаются в рекламу или на сервер. Запросы рекламы разрешаются только после явного выбора пользователя; персонализация, геолокация и AD_ID отключены в конфигурации. При разрешении рекламы SDK может обрабатывать технические данные и IP. Без сети рекламный слот скрыт. Межстраничная реклама не чаще одного раза в шесть минут при возвращении из маршрута в каталог. Нативный рекламный блок пока располагается в отдельном нижнем слоте, а не внутри HTML-карточек. Политика конфиденциальности должна быть опубликована на сайте и дополнена фактическими контактами оператора перед выпуском.

## Правовая подготовка перед RuStore

См. docs/legal-release-checklist.md. Документы public/about.html, privacy.html, terms.html, consent.html, licenses.html являются проектами и входят в тестовую сборку, доступны офлайн. До сборки production необходимо подтвердить публичные реквизиты, согласовать документы, проверить фактическую обработку SDK, опубликовать окончательные версии на подходящем хостинге, и только затем установить переменную окружения android-release SHODI_LEGAL_APPROVED=true. Сборка автоматически отклоняет шаблонные реквизиты и черновики. Не хранить документы личности, домашние адреса без оценки правовой необходимости, банковские сведения и секреты в GitHub. Публичные реквизиты в самом приложении нельзя скрыть от его пользователей.

Реклама является частью сервиса, отдельного переключателя «отключить рекламу» нет. Отказ и отзыв необходимого согласия на обработку данных доступны в правовом разделе; до подтверждения законного основания SDK не запускается. Тестовый APK не является готовым релизом.

Перед выпуском проверяются desktop/mobile Chromium, автономная сборка, npm audit, Android lint, итоговые разрешения APK и отсутствие production ad IDs в тестовой сборке. Виртуальный Android origin в Chromium проверяет только веб-часть, не заменяет проверку реального WebView/рекламного SDK на устройстве. Отзыв согласия останавливает новые запросы приложения; поведение фоновой телеметрии SDK требуется проверить на устройстве.
